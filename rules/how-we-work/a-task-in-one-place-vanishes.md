# A task recorded in one place vanishes when that place is reorganised

**Task type:** how we work — task tracking, and any reorganisation of where work is written down.
**Related:** [`open-decisions-go-in-the-tracker`](open-decisions-go-in-the-tracker.md) — where a
question goes; this is about what happens to it afterwards.
[`board-for-state-sprint-for-commitment`](board-for-state-sprint-for-commitment.md) — the two-file
shape this depends on.
[`silence-must-be-the-alarm`](silence-must-be-the-alarm.md) — a task that stopped being mentioned
looks exactly like a task that was finished.

---

## The rule

> **Every task lives in the tracker. A task recorded only in a plan, a decision row, an architecture
> record or a dashboard does not exist — and when that document is restructured, it is gone with no
> error and no diff anyone reads.**
>
> **And every IDEA becomes a task.** An idea captured in a document and never turned into a row is
> invisible to everyone who reads the board, which is everyone.

## Why: a migration found four, and one of them gated publication

A repo consolidated its scattered work into two files. The sweep covered five places tasks could
hide: flagged rows in a decision log, phase tables in a plan, "what is not verified" lists in
research notes, architecture-record follow-ups, and parked entries carrying revive conditions.

**Four tasks existed in exactly one place.** Any restructuring of those files would have erased
them silently. One was a European data-protection question — whether a trading name satisfies the
requirement to identify the data controller for a sole trader — **which gates publishing the site's
terms, and lived in a single row of a decision log that nothing else referenced.**

Separately, three questions the owner had asked out loud were captured verbatim into an inbox
document, never triaged, and never became rows. **Positioning work continued for a day around the
hole**, producing taglines and pitches that each answered the unanswered question differently.

## Why ideas specifically

An idea document and a task list look like the same thing and are not. **A document is read when
someone goes looking; a board is read at the start of every session.** An idea left in a document is
not waiting — it is out of circulation, and the longer it sits the more confidently people build
around the gap it left.

## Guard

- **When you find a task in a document, move it to the tracker and leave a pointer behind.** Do not
  leave two homes; the second one goes stale and then contradicts the first.
- **Before restructuring any document, ask what exists only here.** That question is the whole rule.
- **Contradictions found during a sweep are findings, not noise.** Two files disagreeing about a
  task's status means at least one is lying to every reader.
- **"Looks done but never marked done" is its own category.** Stale open rows are how a board stops
  being trusted, and an untrusted board is not read at all.
- **Triage an idea capture the same day.** Verbatim capture is right; leaving it uncurated is the
  part that costs.

*Earned from:* a two-file consolidation on 2026-09-11 that found four single-homed tasks, one of
which gated publication, plus three owner-asked questions that sat untriaged for a day while work
was built around them.
