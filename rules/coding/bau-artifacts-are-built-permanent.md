# Anything that becomes business-as-usual is built permanent — never in scratch or temp

**Task type:** coding — pipelines, workflows, scheduled jobs, collectors, reports, configs, and
any file handed to someone else to run.
**Related:** [`scratch-code-lives-outside-the-repo`](scratch-code-lives-outside-the-repo.md)
governs one-off probes and is the *other side* of this line — read both together, they partition
the space. [`"I can't" is a task`](../how-we-work/cannot-is-a-task.md) — handing over a
command is the right move when you are blocked; this is about that command being sound when it
arrives. [`reproducibility`](../research/reproducibility.md) — an output regenerated by
something living in temp is not reproducible.

---

## The rule

**If it will run again, or anyone other than you will run it, or business-as-usual depends on
it — it is built for permanent usage from the first line.** Version control, a durable path, a
real name. Not a scratch directory, not a system temp path, not a session sandbox, not "here for
now, I'll move it later."

That covers: pipelines, workflows, scheduled and cron jobs, collectors, monitors, report
generators, config files, deployment scripts, and **any file referenced by a command you hand to
someone else**.

**File-dependence is fine. Volatile file-dependence is not.** The problem is never that
something reads a file — it is that the file can vanish between writing and reading.

### The line between this rule and its companion

| | Scratch / temp | Permanent |
|---|---|---|
| A probe answering a question you hold right now, that nobody runs again | ✅ | |
| Anything that runs a second time | | ✅ |
| Anything on a schedule | | ✅ |
| Anything another person or process reads | | ✅ |
| A rollback, a handoff artifact, a safety net | | ✅ |
| A patch, a generated config, a fixture, a data file another step reads | | ✅ |

The distinguishing question is not "is this scratch?" — it is **"does anyone other than me, at
any time other than right now, depend on this existing?"** If yes, temp is disqualified no
matter how convenient it was to write there.

**"I'll move it into place once it works" is not this rule.** It fails the way every
deferred-cleanup convention fails: the moving step is skippable, and under load it gets skipped.
Build it in its permanent home and iterate there.

## The incident

An agent prepared a replacement scheduled-job table (`crontab`) for a host running an automated
trading bot. The existing schedule fired over an hour later than intended, because that cron
build evaluates hour fields in system-local time and offers no way to override the zone from the
table itself — so the fix was to rewrite the hour fields in local terms.

The agent could not install it; a permission boundary blocked `crontab` writes from its side. It
correctly handed the operator a command to run instead, and had verified a great deal about the
change: exact three-line diff, identical line counts in and out, which settlement each firing
would cover, that no scheduled event would be skipped or double-covered.

**Both the install file and the rollback file sat in the session scratchpad, mounted `tmpfs` —
RAM-backed, erased on every reboot.** They existed at handoff only because the host happened not
to have rebooted in three days.

Two defects of different severity:

- **The install** would merely fail if the file had vanished. Loud, obvious, recoverable.
- **The rollback** was the safety net for a change to a live system, stored in memory cleared by
  *precisely the event most likely to make someone need it*. A revert path a power cut erases is
  not a revert path.

A third, worse defect hid inside the obvious fix. Replacing the file reference with a pipeline
that reads the live source —

```
crontab -l | sed 's/.../.../' | crontab -
```

— removes the volatile dependency and introduces a **silent** one: if the read fails or returns
nothing, an empty stream reaches the writer, which accepts it. That is not a failed command; it
is an emptied job table. On this host it would have removed not only the trading jobs but the
failover watchdog and the fencing wrapper gating them — a change presenting as success while
disabling the safety machinery.

**Cost:** none realised. The operator caught it — *"But that scratch can be gone any moment."*
The near-miss is the lesson: an agent that had checked line counts, diffs, idempotency and
scheduling arithmetic never checked whether the artifact it was handing over would still exist.

### It happened again, and the artifact was a gate

A subagent was asked to arm a pre-commit gate. It produced a 49-line patch, verified it, had it
reviewed, corrected it once — and left it in the **session-scoped scratchpad** the harness
provides, on the reasoning that a patch file "is scratch". The handover was a single command
asking a second party to apply the patch *from that path*. The reviewer's response was the whole
lesson: **"Why is it in temp, not in the repo?"**

Same failure, different verb, two weeks later — which is why it is recorded here rather than as a
second rule. Three things it adds:

- **A patch is not exempt for being small.** It feels like scratch because it is short,
  mechanical and produced in passing. None of that is the test; the second reader is.
- **The handover is itself the evidence.** If you are handing work over at all, a second party
  exists — which answers the question without further thought.
- **The artifact parked in temp was a gate** — a control a rule had already declared and that was
  not yet running. The one thing most in need of a durable home was judged least deserving of one.

**Cost:** work already done, verified and corrected is lost to a directory reap and has to be
re-derived from a transcript. And **a handover instruction pointing into a temp directory is
unusable the moment it is delayed** — the recipient cannot tell it has an expiry. There is no
error to read: the command reports a path that is not there, long after the context that would
explain it is gone.

## Why this is easy to get wrong

The rule that scratch code lives outside the repository is correct and load-bearing, and it
points at exactly the directory that is wrong here. **A temp path's volatility is a feature for a
probe and a defect for anything recurring.** Same location, opposite requirement, and nothing in
the act of writing the file distinguishes them — the difference surfaces later, in who reads it
and when.

It is also easy to mistake *verified* for *safe*. Everything about the content had been checked.
Nothing about the container had been.

## When in doubt, durable is the cheap side of the bet

This is the non-obvious half, and it is an asymmetry rather than a preference:

- **A durable file that turns out to be single-use costs one deletion.** Bounded, visible,
  trivially reversed.
- **A temp file that turns out to be reused costs the whole rebuild** — and the loss is
  **silent**. Nothing announces that the directory was reaped. No failed command, no log line, no
  diff; only an absence, found by whoever needed the file.

Under uncertainty the bet is not close, and it does not become close by thinking harder about it.
Write it somewhere durable and delete it later if you were wrong. **"I don't know" resolves to
durable**, not to temp.

## Guard

- **Before writing anything that will recur, choose its permanent home first** — repo path,
  committed, named for what it is. If you cannot name where it permanently lives, you do not yet
  know whether it is BAU or a probe; decide that before writing it.
- **Before putting a path into a command for someone else, check what it is mounted on:**
  `findmnt -no FSTYPE,OPTIONS <path>`. `tmpfs` and `ramfs` disqualify it, as does any per-session
  directory the harness creates and reaps.
- **A rollback for a live-system change belongs in version control, referenced by a pinned object
  hash — not a branch tip.** If a scheduled job later commits the changed state over the tracked
  copy, the tip silently stops being a rollback while still looking like one.
- **If you remove a file dependency by piping from a live source, guard the read.** Capture into
  a variable, assert a floor on what came back, and let the chain abort — never let an empty
  stream reach a writer that accepts it:

  ```sh
  t=$(read_the_thing) && [ "$(printf '%s\n' "$t" | grep -c SENTINEL)" -ge N ] \
    && printf '%s\n' "$t" | transform | write_the_thing
  ```

  Choose the sentinel and floor from something load-bearing that must be present, so a truncated
  read fails the check rather than passing it.
- **A patch, a diff or a one-line command is not exempt for being small.** Size is not the test.
- **"I'll move it into the repo once it's applied" is deferred cleanup wearing new clothes.** The
  moving step is skippable, and the handover is exactly the moment attention leaves.
- **Prefer an idempotent form**, so a re-run after an interrupted handoff is harmless — and say
  so when handing it over.
- **State the revert command in the same message as the change command.** A revert discovered
  later is a revert designed under pressure.

---

*Earned from:* preparing a scheduled-job rewrite for a live trading host inside a `tmpfs` session
scratchpad and offering both the install and the rollback from there — after verifying everything
about the change except whether the files would still exist when the operator ran them. Caught by
the operator, not by the agent, who then widened it: anything destined for business-as-usual is
built permanent from the start.

## Enforcement

<!-- machine-readable; verdicts and rationale in docs/gateability.md -->

```yaml
verdict: narrowed
observable: 'the filesystem behind any path handed to a human or referenced by a recurring command - the rule names the command, findmnt -no FSTYPE,OPTIONS'
trigger: 'Stop, plus PreToolUse(Bash) on schedule installs'
check: 'an outgoing message references a scratchpad path -> refuse; a cron or systemd unit references a tmpfs path -> deny'
escape: 'say plainly that the artifact is temporary and not for reuse - which is the judgement the rule asks for, said out loud'
narrows: 'gates the HANDOVER, which is where both incidents surfaced; a reusable file written to temp and read only by a later session names nobody to anybody and passes clean'
fires_late: true
note: 'also guard the pipe-from-live-source fix - assert a floor on what came back, so an empty stream never reaches a writer that accepts it'
```
